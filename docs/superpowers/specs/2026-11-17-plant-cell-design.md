## 1. 意圖

做一個可以「玩」的精美 3D 植物細胞。使用者在瀏覽器裡旋轉、點選、拆解它，邊玩邊讀到每個胞器的介紹。

### 使用者親口說過的

- 要一個「精美」的植物細胞模型。
- 要包含介紹。
- 要可以玩它，不是只能看的圖片或影片。
- 做法選定：Blender 做造型，網頁做互動。

### 使用者沒說、由我假設的

| 項目 | 我的假設 | 理由 |
|---|---|---|
| 用途與對象 | 給一般人或國高中程度的學習者，不需要先備知識 | 使用者沒有說明用途，取最通用的程度 |
| 「玩」的內容 | 第 3 節的玩法 | 我提案後使用者沒有反對，但也沒有逐項確認 |
| 「介紹」的內容 | 每個胞器的名稱與功能說明，加一段開場的整體介紹 | 「介紹」最直接的讀法 |
| 外觀風格 | 第 4 節 | 使用者只說「精美」，把風格交給我 |
| 語言 | 介面與介紹用繁體中文、台灣課本用語，胞器另附英文名 | 使用者用繁體中文 |

## 2. 目標、非目標、反目標

### 目標

1. 成品是**單一個 HTML 檔**，在 Chrome 點兩下就能開，不需要網路、不需要安裝任何東西、不需要啟動伺服器。Safari 盡力支援，不列為必過（見第 9 節）。
2. 細胞看起來精美：有層次、有質感、配色協調，像博物館展品或高品質科學插畫。
3. 每個胞器都能被選到，並顯示正確的介紹。
4. 第 3 節的玩法全部可用。

### 非目標（這次不做）

- 分子層級的寫實或顯微鏡照片般的擬真。
- 生理過程的動畫（光合作用流程、物質運輸等）。
- 動物細胞或動植物細胞對照。
- 多國語言、音效、VR。
- 架站上線。成品是一個檔案，之後要放上網是另一件事。
- Unity 版本。

### 反目標（就算功能都動，出現這些就算失敗）

- 看起來像用球體、膠囊、純色拼起來的課堂作業。
- 生物學錯誤。特別注意：高等植物細胞沒有中心粒；不要畫溶體。
- 用到中國大陸用語（線粒體、高爾基體、胞間連絲）。台灣用語是粒線體、高基氏體、原生質絲。
- 介紹是一大面文字牆。
- 在這台電腦上操作會卡頓。
- 使用者要先裝東西或下指令才能打開成品。

## 3. 玩法

```
┌──────────────────────────────────────┬──────────────────┐
│ 植物細胞                               │ 葉綠體             │
│                                      │ Chloroplast       │
│                                      │                  │
│        3D 植物細胞（外殼掀開一角）        │ 行光合作用的地方。   │
│                                      │                  │
│     拖曳旋轉 · 滾輪縮放                 │ （功能說明）        │
│     滑過胞器 → 微亮並浮出名稱            │                  │
│     點胞器 → 發亮，其他變暗，右側出介紹    │ 你知道嗎？…        │
│                                      │                  │
├──────────────────────────────────────┴──────────────────┤
│ [細胞壁][細胞膜][細胞核][葉綠體][液泡]…    [拆解] [標籤] [測驗] │
└─────────────────────────────────────────────────────────┘
```

- **開場**：一段整體介紹，加一個開始鈕。介紹要說明這個模型是葉肉細胞；植物細胞和動物細胞最明顯的差別是細胞壁與中央液泡，許多植物細胞還有葉綠體，但不是全部都有（例如根的細胞沒有）。開始後外殼的一角移開，露出內部。
- **旋轉與縮放**：滑鼠拖曳旋轉、滾輪縮放；觸控裝置用單指拖曳、雙指縮放。沒人操作時緩慢自轉，一碰就停。
- **滑過**：胞器微微發亮，游標變成手指，浮出名稱。
- **點選**：被點的胞器發亮，其他變暗，鏡頭平順地靠近，介紹面板顯示內容。點空白處取消。
- **構造清單**：底部列出全部 15 項構造，點清單就能選到該項。太小或不好點的（例如核糖體、細胞質）靠這個選。
- **同一種有很多個時**（例如粒線體）：
  - 在模型上點其中一個：那一個最亮，鏡頭靠近它；同類的其他個微亮，讓人看出它們是同一種。
  - 從清單點：同類全部發亮，鏡頭靠近該類的代表個體（有剖面的那一個）。
  - 名稱標籤每類只有一個，掛在代表個體上。
  - 測驗時點到同類的任何一個都算對。
- **拆解**：按一下，外殼移開、胞器由中心向外展開；再按一下收回。
- **標籤**：開關所有胞器的名稱標籤。
- **測驗**：題目給名稱（「請點出：粒線體」），使用者在模型上點。答對答錯都有回饋，結束顯示分數並可重來。測驗中不顯示名稱。
- **版面**：以桌機為主。窄螢幕時介紹面板移到下方，功能仍可用。

## 4. 外觀

- **風格**：半寫實的科學插畫。形狀正確、細節豐富，但顏色乾淨、用色有系統，不追求顯微鏡下的混濁感。
- **細胞外形**：帶圓角的多面體（植物細胞有堅硬的細胞壁，不是圓球），外殼切開一角露出內部。
- **剖面細節**：細胞核切開可見核仁；至少一個葉綠體切開可見類囊體堆疊成的葉綠餅；至少一個粒線體切開可見內膜皺褶。
- **比例**：成熟植物細胞的中央液泡可占細胞體積約九成。為了讓其他胞器看得見，模型會把液泡縮小。這項調整要在液泡的介紹裡寫明，不能讓人誤以為是真實比例。
- **材質**：膜類半透明、有光澤；胞器表面帶柔和的反光；被選中時發光。質感以網頁上實際看到的為準，不以 Blender 的算圖為準。
- **背景與介面**：深色背景襯托細胞；介面面板半透明、字大、留白足。
- **字體**：用系統內建的中文字體，不下載網路字型（成品要能離線開）。

| `rough_er` | 粗糙內質網 | Rough endoplasmic reticulum |

### 每項構造的介紹欄位

| 欄位 | 規格 |
|---|---|
| 一句話 | 25 字以內，講它最重要的工作 |
| 功能說明 | 60 到 120 字，國高中程度看得懂 |
| 你知道嗎 | 60 字以內的小知識，可省略 |

- 介紹文字集中放在一個資料檔，是胞器 id 與文字的唯一來源。
- 介紹文字完成後，要由一位沒參與撰寫的審查者核對生物學正確性與台灣課本用語。

## 6. 做法

### 考慮過的三條路

| 做法 | 成品 | 取捨 | 結果 |
|---|---|---|---|
| Blender 造型＋網頁互動 | 瀏覽器打開就能玩的網頁 | 不用裝東西、容易分享、可在本機直接測試；成品不是 Unity 專案 | **使用者選定** |
| Blender 造型＋Unity 互動 | Mac 應用程式 | 遊戲化空間大；但這台電腦沒有 Unity，要使用者自己安裝數 GB 並登入帳號，分享時對方要下載應用程式 | 未選 |
| 只用 Blender | 模型檔、圖片、影片 | Blender 沒有遊戲引擎，做不出可以玩的成品 | 排除，不符合「要可以玩」 |

### 選定做法之下，我做的技術決定

- **模型用 Python 腳本在 Blender 裡生成**，不靠手動雕塑。理由：可以從指令列重跑，改一個參數就能重新產生整個模型；不找現成的免費模型，避免授權與品質問題。
- **模型匯出成 glTF 的二進位格式（`.glb`）**，網頁用 three.js 顯示。
- **成品打包成單一 HTML**：程式與模型都內嵌在檔案裡。理由：瀏覽器直接開本機檔案時不能另外讀取模型檔，內嵌才能做到點兩下就開。
- **建立本機 git 版本紀錄**，每完成一步存檔一次，不推送到任何遠端。

## 7. 架構

```
blender/build_cell.py ──(Blender 無介面執行)──▶ assets/plant_cell.glb
                                                      │
web/src/organelles.js（介紹文字，唯一來源）              │
web/src/…（three.js 互動程式）  ◀──────────────────────┘
        │
        └──(打包)──▶ dist/plant-cell.html（成品，單一檔案）
```

- **模型與程式的約定**：模型裡每個物件帶一個自訂屬性 `organelle`（只是欄位名稱，值是第 5 節的 id），網頁靠它判斷點到的是哪一項。不靠物件名稱判斷，因為同一種有很多個，而且名稱在匯出與載入過程可能被改寫。這個約定要成立有三個條件：
  1. 匯出時必須明確指定 `export_extras=True`。預設是關的，關著時屬性不會被匯出。（審查者已在這台 Blender 實測）
  2. 屬性不會從父物件傳給子物件，所以每個物件都要自己帶屬性。（審查者已實測）
  3. 多材質的物件載入後會變成一個群組底下掛幾個子網格，滑鼠點到的是子網格。所以網頁要從被點到的物件往父層一路找，直到找到 `organelle`。（依 three.js 載入器的行為推論，尚未實測，要在實作第一步驗證）
- **一致性檢查**：確認模型裡出現的 id 與資料檔裡的 id 完全對得上，而且每個可點的網格沿父層都找得到 `organelle`。`cytoplasm` 若沒有實體物件可列為例外，但要明寫。
- **建議的資料夾配置**：`blender/`（模型腳本）、`assets/`（匯出的模型與檢查用算圖）、`web/`（網頁原始碼）、`dist/`（成品）。

## 8. 限制

### 已在本機查證（2026-11-17）

- Blender 5.2.2 LTS，執行檔在 `/Applications/Blender.app/Contents/MacOS/Blender`，可以不開介面從指令列執行 Python。
- 這個 Blender 有 glTF 匯出功能（`bpy.ops.export_scene.gltf` 存在）。
- Blender 不開介面也能用 EEVEE 算圖（審查者實測）。
- Node.js v22.23.0、npm 10.9.8 可用，而且連得上 npm（`npm ping` 有回應）。查證當下 three 的最新版是 0.187.0，esbuild 是 0.28.2。
- Python 有三個版本，容易混淆：Blender 內建的是 3.13.13；指令稿裡的 `python3` 是 3.15.2；互動終端機裡的 `python3` 被別名指到 3.10.22。建模腳本一律用 Blender 內建的 Python 執行，其他輔助腳本用 Node.js，不依賴系統的 `python3`。
- 這台電腦點兩下 `.html` 會用 Chrome 開（審查者查證）。
- 電腦是 Apple M5 Pro、24 GB 記憶體。
- 沒有安裝 Unity（本專案不需要）。

### 尚未驗證

- Claude 內建的瀏覽器面板能否正常顯示 WebGL 尚未測試；不行就改用 Chrome 測。
- 成品在 Safari 以本機檔案方式開啟的行為尚未測試。
- 成品在較舊的電腦或手機上的流暢度無法在本機驗證，只能靠下面的預算間接控制。

### 已知的技術限制

- Blender 的程序式材質（雜訊、漸層等節點）不會跟著匯出到 glTF。需要的紋理要先烘焙成圖片，或在網頁端重新定義材質。
- Blender 5.x 的 Python API 與網路上多數舊教學不同。寫腳本時以這台電腦上實際的 API 為準，不憑印象。
- three.js 的版本以安裝當下的最新穩定版為準，版本號鎖定在專案設定裡。

## 9. 檢查點與驗收

### 請使用者看的三個檢查點

「精美」是主觀的，所以在動到下一階段前先給使用者看：

1. **模型初版**：在一個只能旋轉的陽春網頁裡看實際畫面，確認形狀與質感的方向後才做互動。Blender 的算圖只在製作過程中內部檢查用，不拿來請使用者核可，因為它和網頁上的質感不會一樣。
2. **第一個可玩版本**：能旋轉、點選、看介紹。確認手感後才做拆解與測驗。
3. **完成版**。

### 驗收條件

- 把 `dist/plant-cell.html` 複製到別的資料夾、關掉網路、在 Chrome 點兩下：細胞出現，主控台沒有錯誤。
- 15 個胞器逐一從模型或清單選到，介紹內容與資料檔一致。
- 拆解、標籤、測驗各完整操作一輪無誤。
- 一致性檢查通過。
- 模型與成品符合第 8 節的預算。
- 介紹文字通過獨立審查。
- Safari：完成版實測一次並如實回報結果，不列為必過條件。
- 最後由一位沒參與製作的驗收者實際操作成品並回報。

## 10. 留給實作者決定的

- 介紹文字的實際內容（須符合第 5 節的規格並通過審查）。
